# 066 — Bounded MVP operations overview

Provide an explicit technical-admin operations view for OPS-09 and RND-01 foundations: runtime software versions, observed API/database transaction reachability, configuration-versus-health distinctions and a bounded review of the current administrator's technical-admin job activity. This follows merged financial UI PR20; it does not repeat or extend advanced finance.

## Clarifications and acceptance checklist

- Protected POST `/api/v1/operations/read`, strict body `{scope:"technical_admin"}`, existing HTTPS/Origin/session/CSRF/current grant, transaction audit before release. Technical administration never grants household/finance/Work visibility. Reuse the reviewed installation membership lock without widening DB grants.
- No probes of network, filesystem, providers, model or Docker socket. Only runtime package metadata and allowlisted configuration booleans leave the backend for this same-origin authorized browser. Never include addresses, paths, credentials, model tags, usernames, raw audit metadata, payloads, entity IDs or other actors' activity.
- Fixed component catalogue distinguishes direct observation, configured-but-unverified, disabled and unknown. Backups/restore, disk/NAS, certificates, worker heartbeat, remote hardware and independent alerts remain unknown. API/database success is not whole-system health; failure sanitizes and clears the complete view.
- Runtime metadata is an installed-version observation, never an approved/stable/licensed/advisory assessment. Unsupported or missing metadata stays unknown. No new dependencies or external lookup.
- Recent job review is the caller's technical_admin jobs created in a fixed last-24-hours window: latest 25, 26th-row truncation signal and fixed status counts. Audit review stays explicitly not_available: runtime deliberately has no audit SELECT grant. OPS-10 scoped audit/reporting remains retained; do not widen permissions for this view. Never a global total, overdue count or periodic monitoring claim. No payload columns are loaded. Bounded SQL timeouts, no retries, no mutations or worker execution.
- Strict client validates exact schema, actor/scope, timestamps/window, fixed unique component/software IDs, status/source coherence, sample bounds/count sums and truncation before display. Hidden tab/navigation/session/grant change, denial and a 60-second request-start deadline clear all state; abort/generation guards suppress late results. No persistence, polling, URLs, downloads or automatic actions.
- Automated unit/client negatives, actual disposable PostgreSQL runtime authority/audit atomicity and trusted HTTPS browser/mobile/failure/privacy evidence. Required make check, dependency/security/privacy review, reproducible dashboard, canonical docs and scope preservation before one commit/push/draftPR. Stop with expected CI, no polling/merge.
