# 037 — Reviewed restored platform-session quarantine

Before exposing a restored development/test database, a trusted operator previews and revokes every unrevoked platform session in bounded reviewed batches, across all scopes and regardless of Work grants or expiry. Preserve passwords, users/scopes/grants, content, job/approval state, session history and previously revoked sessions. No data leaves the private environment.

Require matching explicit restored/configured/actual target, disposable test names, clean READ COMMITTED auth-session/user/audit owner and active technical-admin audit reference. EXCLUSIVE NOWAIT auth_sessions table lock before row locks fences current identity resolution/login/logout writes without changing API code; busy writers or operator rows fail fast. API/consumers must be stopped; there is no persistent startup fence or password reset. The admin reference is independent of any browser session and may itself be signed out.

Plan binds target name/OID/operator, fixed server issue time, chosen limit 1–100, first current unrevoked sessions ordered by UUID (IDs/user IDs/creation/last-seen/expiry only), and has_more. At most 32 KiB; no token/CSRF/password hashes or labels. Apply requires exact plan within five minutes and final age check. Changes to this batch/target/operator/limit/time, replay and empty no-op reject. A replay cannot advance to another batch. Fresh review is required for every subsequent batch; unselected sessions may change without invalidating the currently reviewed batch if membership/order/has_more remain unchanged.

Batch revocation and metadata completion receipt commit atomically. Receipt lists revoked IDs/user references and whether any unrevoked sessions remain under the lock. session_set_clear_at_commit describes only that transaction instant, never full recovery or a persistent ban on later sign-in. Errors/audit/time failures roll back; uncertain commits require metadata/receipt inspection and new preview. Expired-but-unrevoked sessions are included; already revoked timestamps remain unchanged. Final recovery_complete=false and api_activated=false.

No schema, dependency, grant, API/UI/service change or automatic restart. Actual restored token denial, sign-in with unchanged password after deliberate recovery, terminal preservation, multi-batch replay/caps, role/target/time/operator negatives, writer/identity concurrency, atomic rollback, actual CLI/container and copied-session logical restore are acceptance gates. Full local checks/migration sweep and one exact-head four-job CI precede readiness. Work/approval/job/key/source/derived/export/full-host and actual M2 acceptance remain separate.
