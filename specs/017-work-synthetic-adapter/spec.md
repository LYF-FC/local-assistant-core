# 017 — Protected-file synthetic adapter activation

Outcome: a development/test operator can explicitly opt into a single synthetic work adapter using a protected local credential file, then exercise the existing authorized bounded validation-read route. Default install and API remain disabled. No employer content or model. No external data leaves the local application/database boundary.

A lazy source reads one bounded strict JSON bundle only after current cookie/session/CSRF/active workspace membership. Require an absolute owned mode-0700 directory and single-link owned mode-0600 regular file opened via directory FD without final symlinks. Bind schema/environment/database/workspace/OID/expiry; no file DSN, host, arbitrary role or SQL. Secrets use SecretStr and sanitized failures. File removal, expiry or invalid credentials fails closed.

Every authorized read builds a fresh bounded engine using existing endpoint configuration and derived managed login, verifies existing broker profile/RLS/OID checks, and disposes all connections before outer identity authority is released. No cross-request credential or authenticated-connection cache. Credential changes use spec 016: disable workspace first (exclusive registry barrier waits for reads), stop/drain consumers, rotate/revoke, remove/reprepare file, then explicit reviewed re-enable. A file/config change alone is not an instantaneous revocation fence.

Local hidden-TTY prepare validates the disabled workspace/current managed login/24-hour server validity and actual password authentication; emits minimal prepared audit before create-only atomic file publication. Audit may remain if publication fails; no distributed atomicity or secret-restore claim. No auto-reissue/restart or secret printing. Optional Compose overlay mounts a dedicated local volume only in migrate/API; API read-only. Files are plaintext-at-rest within OS/volume permissions, not an encrypted vault. Production/remote/in-flight-network hard deadlines/full-host secret recovery remain gated.

Acceptance: malformed/expired/oversized/symlink/permission/owner/hardlink/duplicate JSON refusal; no unauthorized file access; actual file→managed login→broker scoped read/audit; wrong secret, expiry, removal and rotation/revocation refusal; per-request connection disposal; existing both-commit revocation races and restore remain; opt-in container/TLS smoke with synthetic credentials.
