# 025 — Authenticated synthetic note correction and forgetting

Outcome: a current workspace user explicitly prepares a revision-bound correction or forget request, then a deliberately invoked trusted local executor applies it once. Correction preserves kind/policy, cannot extend retention, and returns the note to draft. Forget scrubs current/history, review hashes and every pending correction payload bound to that note. Owner/date remain explicit or unknown. No UI, real employer content, model/provider, daemon or execution authority.

Reuse the private capture intent/audit infrastructure with immutable intent/target/expected-revision columns and recorded result revision. Capture API/worker accept only capture_draft intents. New strict correct_note and forget_note routes are independently disabled by default. HTTPS/Host/Origin/session/CSRF/current synthetic workspace grant precede credentials. Explicit local change provisioning adds narrow intent-binding INSERT and SELECT of a metadata-only workspace-filtered view, never note mutation or owner credentials.

Correction validates the current visible draft/confirmed revision, policy/kind/retention and fresh active sources/party before private preparation; pending payload contains only proposed synthetic content, not an old snapshot. Forget uses only workspace/id/revision/state metadata, allowing forgotten-source or expired-note cleanup without returning content. Already forgotten, missing or stale targets fail. No guessed replacement owner or extended retention.

Private intent binds current actor/session/nonce/action/target/revision/content and a server lifetime at most five minutes (correction additionally bounded by note retention). Exact pending replay returns the original handle; conflicts, expiry and terminal reuse fail. Status is original-current-session historical metadata, not content authority. Identity audit contains only opaque intent/session IDs. Committed matching identity evidence is required before local application.

Manual executor takes the exclusive registry barrier before user/session/intent/note locks. This deliberately serializes the pilot with all existing work read/write transactions and avoids lock inversion when forget cancels other pending corrections. Current user/session/grant/workspace/revision and correction source/party/retention are revalidated. Lifecycle/history/private audit, outcome and payload/hash redaction plus public operator audit share one database transaction. Duplicate terminal execution returns the historical result. Invalid/orphan/stale/expired requests become denied/redacted; infrastructure/audit/commit failures roll back and remain pending for deliberate reconciliation. No re-confirmation or execution follows correction.

Migration 0015 extends existing private intent storage/guards and adds a security-barrier metadata view. View projects only workspace/id/revision/state/retention, explicitly filtered through the database/workspace-bound active view; ordinary draft RLS/content access stays unchanged. Trusted forget trigger denies/redacts pending correct_note intents in the same transaction, including other sessions' prepared copies, and appends private denial audit. Terminal capture/change intents already contain no content. This is live operational redaction, not physical/backup erasure. Pending unrelated new captures remain independent explicit records.

No new public tables/dependency/SECURITY DEFINER functions. All data stays local. Back up identity/private work together; restore never auto-runs pending. Downgrade refuses while any change intent exists to avoid discarding revision/outcome evidence; use reviewed recovery/reconciliation and verified backup. Existing note/party downgrade guards remain. Independent key/derived/older-backup/full-host acceptance remains open. Exact-head CI, source checks, negative/concurrent/deferred-failure tests, migration/restore and verified HTTPS correction/forget required before readiness.
