# 029 — Selected synthetic Work notes export

Outcome: choose up to ten currently readable notes in one synthetic workspace, explicitly include drafts if wanted, preview their exact current records/source-owner-policy references and retention limit, acknowledge separate-copy limits, then deliberately download a fresh authorized JSON archive. No history, raw debrief, inference, import, cross-workspace bridge or automatic action.

Independent default-false export flag plus existing notes-interface/adapter setup. The deliberate complete-interface overlay includes it. Reuse existing restricted read/inspection grants and private prepared-read audit; no schema, dependency, role grant or server-side content copy. Current HTTPS/Host/Origin/session/CSRF/workspace grant precedes credential access. Lock selected current records in deterministic order; all-or-nothing same-workspace/revision/live-source checks, confirmed by default, explicit draft inclusion. Hidden/expired/forgotten/stale selections fail rather than truncate or silently omit. At most 32 KiB canonical UTF-8 archive.

Preview is an at-most-60-second cancellable snapshot bounded by session/note/party validity. Preserve canonical IDs, kind/state/revision, actor/timestamps, explicit source IDs and current reference labels, policy and unknown owner/date. Unavailable historical owner labels remain unavailable, never fabricated. Copy retention is bounded by earliest selected note/reference retention, independent of short preview/session lifetime. Only current revisions are included. Source labels are registered synthetic references, not durable debrief/transcript provenance.

Download calls the server again with identical selections, draft policy and the preview's canonical content/reference hash. It requires an explicit true copy-limit acknowledgement. Fresh authority/private role/source/version/retention checks and hash comparison precede response; changed content/reference labels cannot silently replace reviewed data. No reused browser-only preview file. Payload hashes stay out of immutable public audit/archive. Metadata-only identity audit records a unique receipt, purpose, record/revision bindings, bytes and declared retention for each preparation, after private read preparation. It proves issuance preparation, not a successful browser save or file lifecycle management. Audit/commit/expiry failure releases no archive.

The browser uses strict scope/binding/schema/size/flag parsing and immutable preview selections; changed selection/options/mutations clear the preview. View/workspace/session change, denial/secret failure, expiry, forget/correction or late aborted response clears selection/preview and cannot create a download. Download uses a cancellable fresh response, short-lived Blob URL and generic UUID-based filename. No local/session storage, URL content, log, background export, persistent browser cache or server export directory.

A downloaded file is explicitly outside Butler's deletion/expiry control. The UI/archive state that fact, show retention and require acknowledgement; public audit receipt is tracking at preparation only, not encrypted storage, destination verification or deletion proof. Ordinary note forgetting must still scrub live content; files/older backups need independent reconciliation. No full key/derived/old-backup/host recovery or real employer acceptance claim.

Acceptance: strict/default/permission-before-secret failures; bounds/duplicates/scope/revision/draft/live-source/expiry all-or-nothing; hash-bound download including changed reference labels; byte ceiling; metadata-only receipt and commit/audit failure release; strict browser parser; actual verified-TLS preview/download and JSON assertions, acknowledgement, mutation/denial/expiry/navigation cancellation with no late file; mobile/desktop screenshot review. Full source/PostgreSQL/restore/security checks; preserve one final PR CI run by completing code/docs/local validation before publishing.
