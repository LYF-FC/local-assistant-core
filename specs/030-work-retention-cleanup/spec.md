# 030 — Manual synthetic Work retention reconciliation

Outcome: a trusted local operator disables one synthetic workspace, previews up to 25 expired metadata candidates, reviews their stable cutoff/hash, and explicitly applies exactly that batch atomically. Reconcile expired live notes/people, pending capture/change/confirmation requests and expired review hashes. No scheduler, API owner credential, real data, source ingestion or automatic workspace enable.

Both preview/apply require matching development/test target, disposable-test naming where applicable, a clean READ COMMITTED table-owner connection, disabled synthetic workspace and an explicitly selected active technical-admin identity. The identity is an operator-selected audit reference, not proof of an HTTP human session. Acquire the exclusive registry barrier before row locks. Ordinary API/scoped roles remain denied even with a forged maintenance setting.

The metadata-only plan binds workspace/operator/cutoff/limit and deterministic candidate IDs, revisions, states and expiry. Cutoff is server-issued, aware, not future and at most five minutes old at apply. Eligible rows must already be expired at that fixed cutoff. Preview lists bounded linked pending corrections, confirmations and review hashes that existing note forgetting will affect; reject more than 100 linked records across a batch. No labels, note text, source/owner data or content-derived hashes appear in plan/output/shared audit. A plan digest hashes only this metadata. New expirations are left for another explicit batch.

Apply recomputes the reviewed plan under the lock and rejects any mismatch, stale/replayed hash, active workspace or lost operator eligibility. Repeating the same plan must not silently advance to another batch. Existing lifecycle forgetting scrubs note current/history/review hashes and pending corrections; party forgetting scrubs labels. Expired requests are denied/redacted, never applied, including orphan preparations and other sessions. Selected note-linked pending confirmations are denied. Review hashes may be nulled independently only by the clean owner in disabled maintenance mode after expiry, with private expiry audit. Unexpired unrelated records/requests/hashes stay intact. Overlapping effects within the same batch are treated as already scrubbed, not another mutation.

All private changes, lifecycle audit and metadata-only local-admin completion receipt share one transaction. Audit/deferred-commit/guard failure rolls everything back. Workspace remains disabled. After an uncertain commit, inspect receipt/current metadata and prepare another preview; a receipt is audit evidence, not bearer authority or automatic retry approval. Do not restore historical payload or extend retention to clean up.

Migration 0016 permits only disabled/owner/expired maintenance forgetting and expired review-hash redaction, preserving normal insert/update guards, forced RLS, immutable history, API privileges and active-workspace behavior. Maintenance lock order is fenced before row locks. Downgrade refuses successful retention evidence rather than erase it. No new table, grant, dependency or model.

Acceptance: strict plan/time/bounds; active/non-synthetic/workspace/role/operator denial; stale/replay/changed linked set rejection; expired versus live records; orphan/cross-session payload and hash scrubbing; byte/linked cap; private/public audit rollback; concurrency/lock timeout and no implicit enable; upgrade/check/downgrade guard; logical restore of redacted rows/receipt and disabled state; actual container CLI preview/apply smoke. Existing real-TLS/browser/security suite stays required. Older-backup resurrection suppression, independent keys/derived/unmanaged exports/full-host recovery remain separate gates, not completed by this tool. Single final PR CI policy remains in place.
