# Authenticated source-withdrawal checkpoints and reviewed older-backup recovery

## Outcome
An operator can retain a protected authenticated file recording selected committed synthetic source withdrawals, verify it offline against independently retained key and file pins, then review/reapply those supplied decisions on an older disabled/no-grant target. An older backup's active source flags and derived copies are cleaned through the existing source-withdrawal authority. No private content leaves the target; only bounded UUID/timestamp/provenance metadata is exported to an explicit local file.

## Requirements
- Export 1–10 sorted unique sources only when registered/inactive, no current/history/pending derivatives remain, and each has a committed successful source-withdrawal receipt. Include the latest matching receipt ID/time for each selected source; do not infer withdrawal merely from an inactive flag.
- Versioned complete metadata contract, distinct purpose/digest/HMAC domains, existing separately retained workspace recovery key, explicit independently pinned key fingerprint and expected file digest before target DB access. Protected bounded owner-only no-follow/no-overwrite file I/O; no candidate-discovered trust.
- Offline verify has no database dependency. Missing/partial/unsigned/substituted/cross-purpose/wrong-key/namespace/pin/checkpoint/oversized/duplicate-JSON input refuses. Shared recovery master key reuse is explicitly domain separated; no new key material in logs/output/audit.
- Target requires the same explicit actual/configured DB/OID, active technical-admin reference, disabled synthetic workspace, zero grants and existing clean-owner fail-fast barriers as manual withdrawal. Selected target sources must all exist; absent source IDs refuse rather than silently reduce coverage or create tombstones/bindings.
- Exact five-minute outer review binds the verified file digest, export/source receipt provenance, public auth references and complete current source-withdrawal plan. Recompute on apply; reject changed/stale/replayed/no-op plans and future source exports. Existing 25-note/100-effect/32-KiB caps stay; no partial withdrawal.
- Existing source cleanup receipt plus a second file-bound reconciliation receipt commit atomically with all effects. Export preparation audit commits before protected file persistence and never claims independent retention; file errors produce no success output.
- No schema/grant/API/dependency/default/service or automatic activation change. Existing note/party file formats stay compatible and are never accepted as source checkpoints. Supplied decisions are not proof of latest/complete source withdrawal, original-file deletion, absent-ID resurrection prevention or full host/key recovery. Always deny recovery/activation completeness.

## Acceptance
Contract/security negatives before any database connection, real source receipt export and wrong/incomplete state refusal, exact authenticated recovery with old flags/copies, rollback of both receipts/effects, capacity/authority/concurrency reuse, offline CLI and independent same-key older-file checkpoint substitution. Real dump before withdrawal, file export after actual newer source withdrawal, verified file reapplication on the older restore, post-cleanup dump preservation and non-root maintenance-container CLI. Full four-job CI and canonical status remain mandatory.
