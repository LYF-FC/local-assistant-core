# 021 — One-time synthetic note confirmation

Outcome: the current authenticated workspace user explicitly requests confirmation of an exact prepared review. The API queues metadata; a trusted, manually invoked local executor confirms the reviewed synthetic note once. Queued does not mean applied. Historical status does not authorize current content or execution.

Default disabled independently of review/adapter. HTTPS/Host/Origin/session/CSRF/current grant before storage. Server binds workspace, record, revision, actor, session and five-minute receipt expiry; strict client nonce plus explicit confirm_note intent. No content/hash/source list in public queue/status. Replays return the same request only for its current actor/session/workspace; conflicting bindings fail. No API lifecycle/owner credential.

Executor uses one owner connection and one READ COMMITTED transaction in the same database. Registry barrier, user, session, request, draft and receipt lock ordering precedes fresh active/grant/source/revision/hash/retention/receipt checks. Both review and enqueue must have committed identity audit evidence. Orphan private preparation is insufficient. A unique private consumption ledger, lifecycle revision/history/audit, public outcome and outcome audit commit atomically. Terminal replay makes no new mutation. Stale/revoked/expired requests become denied without consumption. Infrastructure/audit/commit errors roll back and leave pending for deliberate retry.

Synthetic dev/test only. No background scheduler, model/provider, employer data, capture/correction/forget UI, parties, document keys or execution approval. All data remains local. Existing forget scrubs receipt hashes; immutable consumption/queue retain minimal identity/outcome metadata only. Back up identity and work together; restore never auto-runs pending requests. Rollback requires stop executor and disable flag first; downgrade removes queue/consumption metadata so take verified backup first.

Acceptance: strict/default/permission failures before private access; real restricted-login enqueue then owner-only atomic application and idempotent status; cross-session/nonce/source/revision/expiry/revocation failures; orphan evidence rejection; concurrent worker duplicate; audit/ledger failures roll back everything; API/role mutation denial; migration round-trip, restore and opt-in TLS exercise. Exact-head CI required before review readiness.
