# 036 — Reviewed restored no-op execution quarantine

A trusted operator explicitly selects up to 25 combined approval/job UUIDs in one known scope of a restored development/test database, reviews a metadata-only plan and quarantines their outstanding no-op execution authority. Pending/approved validation.noop approvals become cancelled through existing sealed transitions. Queued/running no-op jobs and their paired outbox become dead_letter with restore_quarantined result and cleared lease hash/deadline. Consumed approvals, completed request/job history, unselected IDs, other scopes and payloads remain unchanged. No data leaves the private environment.

Require explicit configured/actual restored target, disposable test names, clean READ COMMITTED table owner and active technical-admin audit reference. Selection must be unique/sorted/nonempty, at most 25 combined IDs. Missing/foreign/unknown-handler/unbound approval or inconsistent job/outbox linkage rejects all. No unreviewed partial auto-selection; explicit selected coverage is not a global recovery certificate.

Acquire EXCLUSIVE NOWAIT table locks on approvals/jobs/outbox before row locks. These conflict with normal row-locking/mutating API/worker transactions, including INSERT, without runtime code/schema/grant changes. Ordinary reads remain possible. Busy tables or operator rows fail fast and roll back; services/workers must be stopped. These short database-wide locks temporarily affect other scopes too. No persistent startup fence: fresh authority can be created after commit if operators restart applications prematurely.

Plan binds target name/OID, scope/operator, selected state/decision metadata, outbox identity/attempts/availability/lease deadline/presence and fixed server issue time; no payload, payload/idempotency/lease hash or token value. Maximum 32 KiB and five-minute exact review, rechecked before commit. Changes/replay/all-terminal no-op reject. Existing terminal rows can be inspected but are preserved. Changes, per-item metadata audit and completion receipt commit together; failure rolls back. Old lease finish/retry is rejected and quarantined jobs cannot be claimed.

No schema/dependency/grant/API/UI/service change, auto execution/retry/reactivation, password/key/session reset or global latest/full-host claim. Actual restored-session revocation, Work quarantine/forgetting/pending-input cleanup, credentials/keys and external receipts remain separate. Only validation.noop is handled; future external/ambiguous writes require a separately reviewed reconciliation path. Acceptance: real API-created authority, queued/leased jobs, retained terminal/unselected controls, unknown/foreign/inconsistent negatives, exact review/time/cap, audit rollback, writer/worker concurrency and old-lease fencing, actual CLI/container and old-dump restore plus full local/one exact-head four-job CI.
