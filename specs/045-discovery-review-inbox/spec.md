# Discovery review inbox and reviewed digest

## Outcome
Search/filter saved Discovery ideas and proposals across the currently authorized private inbox, deliberately select a bounded set, review evidence/unknowns/provenance, then download a freshly rechecked cited digest. Deliver backend filters, review/export authority, accessible workflow, privacy lifecycle and complete verification in one PR.

## Requirements
- Server-side bounded search (literal title/summary substring), exact topic, stage and current interest filters intersect with existing owner/current-private-scope/active/unexpired restrictions, ranking, dismissed choice and cursor paging. Changing filters restarts paging. Do not imply complete/global snapshots or generalized topic preferences.
- Select 1–10 displayed records with exact expected revisions in one explicit private scope. Reject duplicates, mixed/cross-owner/cross-scope, malformed/expired/forgotten records, stale revisions and over-budget payloads as a whole. No automatic paging/selection or subset fallback. v1/v2 ideas/proposals remain supported.
- Preview and download are authenticated Origin/CSRF-bound local reads, with current user/session/scope and record locks held through audit/commit. Recheck time/session after lock waits. A 60-second maximum deadline also respects session and earliest selected expiry. Preview records a minimal immutable audit receipt binding public review ID, hash, current session, scope, count and deadline; no server content copy.
- Download requires that exact committed preview receipt/hash, unchanged ordered selection/content, current authority, unexpired review and explicit unmanaged-copy acknowledgement. Reuse existing append-only audit storage. Migration 0019 adds only two fixed-search-path, non-public SQL helpers: lock one chosen private membership and verify one bound review deadline. Runtime gets EXECUTE on those helpers, not audit SELECT or scope UPDATE. No content table/secret/service. Each response has a fresh export ID. Audit/commit failure releases no response/file; receipts prove preparation, not saving/deletion. Hashes bind content/current session, not action authority or source truth.
- Reviewed digest shows every selected idea/proposal, current interest, summary, manually reported evidence/observed date, assessments/unknowns, feedback, record revision/UUID/source metadata and expiry. No evidence is invented or fetched; interest never becomes approval. Full selection is checked again before Markdown is built from the fresh response. Title is a browser annotation and never sent to the API.
- Bounded JSON (64 KiB) and escaped Markdown (128 KiB), no truncation. Dynamic URLs remain literal code text in the document, not generated links. Stable citations, public UUID-only filenames, explicit selected scope/coverage, checked/prepared time and copy deadline (or no stated expiry) preserve provenance. Copies are separate/unmanaged and cannot be recalled after forgetting/expiry.
- Selection/title changes revoke preview/ack; inbox filter/paging/read/write/refresh, creating/editing/feedback, close, expiry, denial, session change and unmount clear/abort review and suppress late payload/file side effects. Revoke Blob URLs. No localStorage/autosave. Do not reuse feedback/detail-conflict semantics for stale digest review.
- No source collector, scheduler/notification, model, external send, generalized preference, deduplication/installation/adoption authority, Work bridge, dependency/credential or production activation change; no broad table grants. Data leaves only as deliberate local unmanaged download; development/CI are synthetic-only.

## Acceptance

Actual PostgreSQL covers restricted runtime, row-lock concurrency and receipt preservation/rollback. Pure client tests cover strict parsing, exact fresh transport, escaped cited Markdown/URL literals/caps. Actual HTTPS covers full inbox-to-download, fresh IDs/hash/ack/title exclusion, edits/invalidation, refusal, expiry/unmount, cancelled late real responses and responsive screenshots. Complete make check/security/policy plus all four final exact-head hosted checks; record CI in PR metadata without an evidence-only push. Roadmap stays unchecked until merge; full Discovery/host/real Work gates remain separate.
