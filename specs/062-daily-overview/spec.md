# 062 — Scoped daily overview and review entry

## Specify

An authenticated member explicitly opens Daily overview, selects one granted household/member-private scope and a day/timezone, then reviews a bounded day agenda/open due tasks, their private in-app reminders and documents requiring text review. Cards explain stale/offline/conflict/uncertain/paused/unavailable/truncated state and open the existing scoped panels for current review/actions. This advances baseline CORE-08/09, UI-01 and ORG-02; it does not implement newly deferred REV work or certify a complete MVP/dashboard.

## Clarify / scope decisions

- Reuse existing protected briefing, reminder-list and document-list APIs/strict parsers, current grant/audit and owner rules. No backend route/schema/grant/worker/provider change. Read projections are not a new queue or authority store. A shared scope does not expose somebody else's private reminder inbox; reminder owner stays current user. Technical administration grants no document/task/calendar data access.
- Keep current session landing behavior; Daily overview is an explicit navigation view. Choose only supported scopes present in the current session, preserving existing private-first preference. No all-scope counts/queries/search. Date defaults use the browser's local calendar date and an explicit supported IANA display timezone (UTC fallback), not UTC date slicing. Installation setup defaults do not rewrite domain preferences.
- Load exactly three first-page requests in parallel; no automatic pagination, polling, refresh or retry. Briefing bounds remain 25 calendars/100 events/25 tasks/10 memory references. Reminder/document lists remain at most25 each. Clearly label first-page/truncated lists and do not claim globally complete totals or atomic cross-service authority. Documents are a first-page sample of all authorized documents: filter pending/error cards locally and disclose that later pages may contain more. Do not label unreviewed text as approved invoice/filing authority or claim a global approvals/worker-health inbox.
- On any authentication/permission denial, clear all overview data and prevent late component results leaking back;401 also signs out. Other component failures show unavailable, not empty/success, while successful independent sections remain usable. Invalid/mismatched payloads fail only that section, display sanitized errors and never echo raw response content. All results wait for the batch to settle before publication. Abort/generation guards reject responses after changed scope/day/timezone/view/session, including a transport that ignores abort.
- Expires no later than 60seconds from request start or briefing valid_until, whichever is sooner. An expired view clears all cards and requires explicit refresh; no stale card/action keeps secret details. Hide data immediately when document visibility is lost; regain visibility requires refresh. Failed or overlong requests never make an old result current. Unmount/session/scope changes clear all in-memory data. No storage/cookies/URLs/export files contain overview payloads, and no content is sent outside the local origin.
- Open-document actions pass only an authorized metadata target, then existing panel rereads current source under server authority. Task/reminder/calendar entry retains selected scope, day/timezone where applicable; existing controls reread before mutations. No mutation, confirmation, download or reminder acknowledgement occurs in the overview. Overview expiry is not write authority and does not bypass destination checks.
- New UI remains responsive and uses semantic regions/status/labels. Source strings render as text. Retain existing standalone panels/session landing behavior and their contracts. No default broad search or new model request.

## Acceptance / checklist

1. Bounded parallel same-origin no-store reads and owner/scope/source binding; partial service failure, malformed receipt, denial, abort/late results, timeout and explicit retry only.
2. Scope navigation, current-source reread and correct destination context; revoked/admin-only/mismatched owner/scope data withheld, no cross-user metadata/count leak.
3. Freshness expiry, hidden-tab clearing and selection/view/session clearing. No automatic polling/pagination, persistent browser state, model/provider request or direct mutation.
4. Synthetic trusted HTTPS browser: agenda/tasks/private reminders/pending and failed documents, empty vs unavailable/truncated/unknown, mobile and source navigation; delayed requests and revocation cleared. Existing container owner matrix unchanged.
5. Required makecheck/client/build/appropriate hosted interface+container selection, privacy/canonical/full155scope consistency and convergence. No backend/schema/grant changes means no new local nativePG/migration evidence is claimed. One commit/push/PR then stop with expected CI.
