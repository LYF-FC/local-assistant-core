# Spec 076 plan

## Constitution and dependency review

Preserves FastAPI/PostgreSQL/React, explicit scopes, restricted runtime role, append-only history, revision fences, commit-before-release auditing and local-only data. No migration, permission, trigger, rate-limit, CORS, proxy-trust or authentication change. New backend surface is limited to an opt-in worker flag and a guarded synthetic ledger module; new frontend surface uses existing routes. Dependencies unchanged (locked uv/npm).

## Architecture decision (proportionate, with limits)

Options considered for the durable synthetic collaborator:

1. **Marked directory ledger on a named Docker volume (chosen).** Same exclusive-publish semantics the process-restart tests already proved (`os.link`, fsync), but promoted from test infrastructure to a guarded, explicitly opt-in module, so durability does not depend on the worker process or its transaction. Smallest change; no new service, role or schema.
2. A PostgreSQL table in the same database — rejected: it would share the worker's database and could be rolled back with or restored alongside the very records it is meant to be independent of, and it needs a migration/grant change.
3. A sidecar HTTP destination service — rejected as disproportionate for a metadata simulation and not approved.

Limits: bound to one volume, not replicated, not a filing adapter; documented in the spec and owner guide.
