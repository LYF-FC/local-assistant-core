# 047 — Durable local task reminders

## Specify and clarify

A task creator can explicitly choose one reminder time, receive a private in-app notification, acknowledge it, reschedule/snooze or cancel, inspect its metadata history and export a current inbox page. A deterministic restricted worker survives restarts and atomically records delivery without a model, external provider or browser being open. In-app delivery means availability in Butler, not proof the person saw it or device push.

- Only the existing three task scopes are supported. Reminders are creator-private even for household-shared tasks; a shared reader cannot schedule or inspect another person's reminders. Human scheduling pins the current task version and reminder revision; acknowledgement/cancellation pin the reminder revision and current owner/task authority, with an open task required for acknowledgement; every POST is HTTPS/Origin/CSRF protected.
- One reminder record per task, with sealed owner/task/scope, optimistic revision and increasing schedule cycle. States: scheduled, delivered, acknowledged, cancelled. Scheduling or snoozing uses an explicit aware future instant within 365 days. Acknowledgement never completes the task. Repeated/concurrent worker passes cannot redeliver a cycle in one database timeline.
- Reminder dates are independent of task due dates. Task detail/due corrections preserve the reminder and it resolves current authorized task content at read time; no title/details/source text is copied into scheduling/history tables. Closing/forgetting a task cancels scheduled/delivered reminders in the same API transaction. Reopening does not silently reactivate them. The worker independently refuses closed/forgotten tasks or inactive/revoked owners.
- Per-owner preferences apply across task scopes: enabled, IANA timezone, minute-based quiet start/end and daily delivery limit 1–20. Fixed revision-0 defaults: enabled, Europe/Paris, 22:00–08:00 and five deliveries/day; changing their meaning requires a reviewed migration. Equal start/end means quiet hours off. UTC iteration through real zone rules handles DST gaps/folds. Policy changes cause due deferred records to be reconsidered; paused owners are excluded from candidate scanning without destroying requests.
- Delivery and daily accounting serialize on the recipient user row, then membership/task/reminder locks. A worker uses explicit persisted scheduling authority, not an expiring browser session. Each individual delivery/defer/cancel, immutable metadata event and minimal system audit commit atomically. Crash-before-commit rolls back; repeated workers see committed state. No external side effect, lease or provider receipt is implied.
- Due batches are bounded (100), deferred until quiet hours end or the next allowed local day, and contain no private content in operational output. Worker loop is an explicit Compose profile, stopped by default; no owner stack is activated by development. Default web requests do not run the worker.
- Inbox pages are scope/owner filtered, bounded to 25 and live UUID-keyset ordered. Current task text is omitted for forgotten tasks. Delivery history is metadata only and owner-paged. Explicit acknowledged JSON page export is unmanaged, not a whole-collection backup. Old backups/downloads may retain prior state/content. A restored older database can reintroduce pending intent: keep workers stopped until reviewed recovery/authority quarantine; one-timeline deduplication is not cross-restore replay prevention.
- UI drafts/history/copy acknowledgement are ephemeral and cleared on scope/session/navigation/denial; abort/late results cannot restore old content. Conflicts keep drafts pending explicit discard/reload. No automatic mutation retry. A worker preference is not a startup/production certificate.

## Acceptance

API/worker lifecycle and authorization negatives; atomic task-close/forget cancellation; immutable identity/history and restricted grants; actual concurrent worker/budget/owner revocation and audit rollback; quiet hours/DST/daily limits/policy revision changes; restart/catch-up and repeated-pass deduplication; schema down/up and actual logical restore; responsive real HTTPS create/change/inbox/ack/history/export/denial/conflict/cancellation checks; all four final-head jobs.

Data leaving: none automatically. Explicit JSON download creates a local unmanaged copy. No email/phone/OS push, recurring routine, calendar/provider action, AI, business/care/finance/Work reminder or production activation is delivered.
