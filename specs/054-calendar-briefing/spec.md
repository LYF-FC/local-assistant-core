# 054 — Bounded calendar reconciliation and daily briefing

## Specify

A member imports a complete, normalized synthetic calendar window, reconciles it without duplicate occurrences, sees changes and stale/offline state, and opens a deterministic day briefing alongside current open task deadlines and confirmed memory references. No network calendar client, credentials, model, external write, dispatch or scheduler is introduced. ORG-01/02, CORE-08/09, UI-01 and MVP-02 remain partial until live-provider and full dashboard/briefing acceptance.

## Clarify

- Only the three existing household/shared and creator-private scopes; current membership plus creator for private content. Shared readers see current calendars; only creator imports, marks unavailable, exports history or forgets. Admin grants do not imply content access. Source scope/owner/identity are immutable.
- A source is a local record, not an account. User-supplied labels/UIDs/cursors/text are untrusted content, never URLs/actions. No ICS/CalDAV parsing, account provisioning, automatic polling, recurrence rule expansion or provider activation. The adapter boundary accepts already expanded occurrences with provider UID and stable recurrence ID (empty for a singleton), sequence, aware instants or exclusive all-day dates, and explicit IANA timezone. Preserve original recurrence identity for moved exceptions. Reject floating times, non-UTC offsets inconsistent with the stated zone (UTC instants are accepted for portable reimport), impossible dates, duplicate identities, backwards sequences or changed content at equal sequence. Same-title events remain distinct; no inferred cross-source deduplication.
- Complete full windows cover 1–31 local dates, at most 100 occurrences/64 KiB serialized data. All-day dates remain dates; timed events normalize to UTC and retain source zone. Every occurrence overlaps the claimed coverage. No partial-page/delta acceptance. Omission counts as removal only within overlapping old/new coverage; outside coverage is unknown. A moved instance outside coverage is not certified deleted. Recurrence expansion/provider pagination correctness remain adapter gates.
- Optimistic source revision plus cursor and fetched timestamp prevent stale application. Identical snapshot replay is a successful no-op, including after lost acknowledgement; cursor reuse with differing content, older fetches and conflicting event sequences refuse atomically. Each accepted changed window advances one revision and sealed source history. Stable occurrence IDs derive from source UUID and UID/recurrence tuple, never titles/times. Incomplete/offline attempts retain last good data and explicitly mark unavailable; only a fresh complete snapshot recovers it.
- Limits: 10 total sources per creator (including tombstones), 100 stored revisions per source (forget still allowed), 25 source cards per scope page. Exports/history are owner-only, five revisions/page with explicit unmanaged-copy acknowledgement; all copies/backups remain outside recall. Forget irreversibly scrubs current and every historical payload, retaining minimal identity/version/timestamps. No per-event forget; disconnecting/unavailability is not deletion.
- Day briefing uses explicit date and IANA display zone, DST-aware local midnight bounds, one scope, at most 25 visible sources, 100 occurrences, 25 open dated tasks and 10 confirmed/unexpired memory titles/source references. Each section exposes truncation; undated tasks and other scopes are not inferred absent. Calendar coverage/freshness/unavailability stays visible, even when no events match. Overlaps flag possible conflicts, never select a winner; all-day entries are not time conflicts. Memory is unranked context, not inferred household needs. No mutation, completion, hidden automatic summary or generated advice.
- User/session/scope locks precede source/task/memory row locks and audit commit; recheck session expiry after waits. All protected responses require metadata-only audit commit. Audit never stores event text, UIDs/cursors, payloads or briefing content. Server-side permission checks apply to every operation. Browser results/drafts are in memory, aborted/cleared on scope/view/session change, expire within 60 seconds/session expiry, and never retry mutations automatically.

## Acceptance/checklist

1. Synthetic replay, update, cancellation/omission, moved recurrence, rolling coverage, offset/DST/all-day and exact stable-ID tests; conflicts/invalid/partial requests retain current data/cursor/history.
2. Actual PostgreSQL restricted role, immutable identity/history, monotonic revisions, bounded quotas, row-wait expiry, concurrent stale writes, current grants and audit failure rollback/release tests.
3. Shared/private/admin/revoked/CSRF/origin/session negatives across reads, briefing, import, history/export and forgetting; no content in audit/errors.
4. Deterministic day briefing combines only current authorized calendar/task/memory references; stale/offline/unknown coverage, overlap, truncation and model independence remain visible.
5. Logical dump/restore preserves IDs, window/provenance/history and forgotten scrubbing; migration down/up and role setup are repeatable. No host/full-MVP recovery claim.
6. Trusted HTTPS desktop/mobile UI imports normalized JSON with preview, shows current source and reconciliation, briefing, history download and explicit forget confirmation. Client parsing, inert text, abort/late-response, no browser persistence and negative flow tests.

Data leaving the private environment: none automatically. An explicit local download creates an unmanaged copy. Synthetic fixtures only; private deployment unchanged. Live calendar read/writes/mirror, real-model quality/activation, recurrence delivery, installation identity/configuration and complete operational acceptance remain separately gated.
