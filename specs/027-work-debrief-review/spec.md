# 027 — Synthetic text debrief review

Outcome: explicitly start a sample text debrief in the existing optional Work notes screen, prepare bounded proposals from labelled lines, compare each proposal with its original line, edit it and deliberately request a draft save. Continue through existing pending/recovery, separate local application and revision-bound confirmation. This is a deterministic annotated-text pilot, not natural-language inference or full spec 005 acceptance.

Input: at most 3000 ASCII characters, at most 10 nonblank lines, each `Observation:`, `Action:`, `Decision:` or `Question:` followed by 1–246 permitted sample-text characters. Case-insensitive labels, CRLF/LF and blank lines are supported. Reject the entire input with a line-specific fixed error if any line is invalid; never silently omit, truncate, merge or deduplicate. Preserve original line number and exact quote for review, including whitespace. Names/dates in text are not parsed into authority. Owner/date remain explicitly unknown. No imports, URLs, markdown execution, recording, model or external action.

Preparation happens only in transient browser memory and sends no request. It is available only inside a successfully loaded authorized synthetic workspace catalogue with capture enabled. Every eventual save uses existing current-session capture validation, explicit selected registered source(s), policy and retention, original nonce recovery and manual executor. Existing source selection is not proof that the transient debrief is a registered source. Original quotes/line numbers are ephemeral review aids and are not persisted provenance. Only the explicitly reviewed note body and chosen registered source references are stored by the existing API. Raw transcript storage/lineage/voice and arbitrary prose extraction remain future work.

One selected proposal opens the existing editor with exact text and kind. Editing never modifies its source quote or another proposal. Per-line status distinguishes not requested, uncertain, pending, applied and denied; no applied label before a matching capture request outcome. Pending/uncertain actions block other saves. Explicit same-request retry/recovery stays bound to the proposal and nonce. A denial permits deliberate re-review; duplicate wording on different source lines remains distinct. Discarding/replacing the debrief clears raw text, quotes, selection/editor and frozen debrief request payload, while preserving only existing minimal request metadata for reconciliation. Individual omission is explicit and cannot hide an in-flight request.

Reload/view/workspace/sign-out, access/credential failure, preview expiry and aborted late responses clear the debrief with existing private-state cleanup. Its lifetime cannot extend the existing maximum-60-second catalogue deadline. No browser persistence, new API/schema/grant/dependency/audit bypass or outbound data. No family source, silent capture, batch save, automatic confirm/execution or claim of real-data/isolation/recovery acceptance.

Acceptance: parser boundary/error/source-span/unknown/dedup/injection tests; actual verified-TLS browser multi-line prepare/edit/save/recovery/manual apply/confirm and explicit omission; no preparation network write; ambiguity/status nonce binding; mobile/desktop screenshots; expiry/discard/denial/view-switch cleanup with no late restoration. Run make check and exact-head CI including existing PostgreSQL/restore suite. Mark roadmap prior implementation review merged; this delivery stays In progress until merge.
