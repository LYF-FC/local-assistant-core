# Simpler manual capture and later Discovery enrichment

## Outcome
Resolve the manual-entry friction reported in issue #33 across Memory and Discovery as one complete capture/enrichment workflow, rather than another selected-note projection. Save an honest evidence-free idea first; add evidence and assessments later through revision-bound correction. Preserve the full existing proposal flow and Memory provenance/history/forgetting.

## Requirements
- Discovery quick capture requires an idea summary and visible owner-private access; show a deterministic editable title suggested from the first nonblank line. Topic may stay explicitly unclassified. Do not create a source URL, observed date, assessment, confirmation or approval to fill a hidden requirement.
- Persist new ideas as version-2 discovery_proposal envelopes with explicit stage=idea, empty evidence, tentative assessment and unassessed fields. Existing version-1 evidenced proposals remain valid and unchanged. Version-2 proposal stage requires real manually supplied evidence with the existing URL/date/count bounds. Invalid/mixed envelopes refuse.
- Owner-only current-scope/session/Origin/CSRF creation and expected-revision detail enrichment reuse existing Memory transactions, row locks, revision history, redaction/forgetting and minimal audit. Enrichment requires typed topic/summary/title/evidence and preserves feedback, owner/scope, expiry and existing assessment. Only canonical idea source-reference text is updated to the manually reported proposal reference; custom source metadata stays intact. Concurrent feedback/detail changes cannot overwrite each other. Audit/commit failures roll back content/history.
- Interface distinguishes Idea - no evidence from Manually reported proposal, offers full proposal entry and later editing/enrichment, keeps all evidence entries unless explicitly changed, exposes unknowns, and never treats interest as action authority. Conflict retains the draft until explicit discard/reload; refusal/session changes/unmount clear private state. No source fetch or model call.
- Memory new entry keeps content/access/type visible, suggests an editable title from content, defaults new assessment to visibly Tentative, and moves source/assessment/optional expiry detail to progressive disclosure. Temporary context expiry stays visible and required; existing corrections preserve source-maintained structured content and metadata. No silent scope change or generated evidence. Existing saved entries retain their assessment.
- Title suggestion is deterministic, bounded and Unicode-safe; full content is preserved. Local drafts are memory-only, with no localStorage/autosave/backend request until deliberate submission.
- No schema/grant/dependency/connector/production activation change. Normal existing explicit API writes remain local. Synthetic fixtures only for development/CI; real Work-data gates remain independent. No household/work bridge.

## Acceptance
Cover v1 compatibility, strict v2 stages, idea unknowns, complete enrichment/history/feedback/forgetting, owner/scope/session/CSRF refusal, stale/concurrent edits, audit/commit rollback and current SQL runtime guards. Pure client checks cover parser/title bounds. Real HTTPS browser tests cover minimal Memory/idea capture, progressive controls, explicit evidence enrichment/multiple-source preservation, conflicts/denial/cancellation and responsive layout. Complete make check/security/policy and final exact-head four-job CI. Record actual evidence in PR metadata without an evidence-only source push. Delivery stays unchecked until owner merge; #33 remains open pending merged delivery/owner UX acceptance.
