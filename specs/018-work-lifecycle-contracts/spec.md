# 018 — Synthetic work record lifecycle contracts

Outcome: establish executable, immutable contracts for a synthetic work draft before implementing storage/capture. Distinguish draft, human-confirmed, expired visibility and terminal forgotten state. Preserve unknown owner/deadline; human note confirmation is never execution approval. Corrections reset confirmation and cannot silently extend retention. All snapshots are redacted by a forgetting plan; bounded current-only export excludes expired/forgotten and defaults to confirmed records.

This is a deterministic library and synthetic tests, not a database store, authorization service, HTTP endpoint, debrief capture or background job. Existing Work content gates remain pending. Workspace IDs and actor metadata are not transferable authority; future adapters must resolve current user/session/grants and source membership under existing transaction locks. No data leaves the local process. No dependency, schema, active retention default, employer content, model, key material or deployment.

Require an explicit workspace-bound retention policy and aware server time; no implicit retention setting. Future database implementation must atomically compare revision, persist transition/private audit and source checks, redact every historical payload and source association on forget, invalidate derived context/index/job/export copies and maintain suppression-ledger/backup reconciliation. Key/namespace/recovery design is documented but not implemented. A Python projection cannot erase previous references, disks, indexes or backups.

Acceptance: field/identity spoofing rejected, immutable tuples/snapshots, workspace mismatch, stale revisions, naive/backward clock, unknowns, ungrounded confirmation, correction reset/non-extension, expiry boundary, terminal forget/all-history redaction and bounded workspace-only current export; malformed/cross-workspace history refused. Canonical docs/Kanban distinguish verified contract from future persistence. Full current CI stays green.
