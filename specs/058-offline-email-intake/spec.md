# 058 — Bounded offline forwarded-email intake

## Specify

A creator imports one synthetic `.eml`, preserves its exact original bytes and one original attachment, opens the existing unreviewed document/invoice workflow, safely replays an exact message, inspects original-mail provenance, downloads it with copy-limit acknowledgement, and forgets the document/envelope/derived history atomically. This advances DOC-01/email provenance and DOC-03/MVP-03 dependencies without live mailbox credentials/polling, sends, filing effects, model inference or private deployment changes. No data leaves the installation.

## Clarify / checklist

- Reuse document scope/grant/session/CSRF/origin authority and exclusive owner serialization. Exactly one attachment/document per envelope; one new protected table links immutable initial source revision 1/attachment checksum to raw email. Current shared documents remain shared, but raw email/provenance is creator-only even for shared documents; admin/same-private-grant does not override ownership. Message headers/body are untrusted source data, never identity, tool authority, links to fetch or rendered HTML.
- Canonical base64 upload, at most262144 raw bytes,4096 physical lines,1024 bytes/line, four Content-Type header lines and eight delimiter-like lines before standard-library parsing. Strict `multipart/mixed`, at most two direct leaves (optional plain-text body plus exactly one attachment); no nesting, HTML, alternative/rfc822 messages, defects or duplicate MIME/security headers. Attachments require strict canonical base64, safe basename and matching `.txt`/`.md` text/plain or `.pdf` application/pdf type, existing 128KiB original/32k text/PDF worker limits. Ambiguous/multiple/unsupported messages fail atomically, never silently drop an attachment. Parser does not fetch anything or execute source text. Standard library only; no new dependency.
- User-supplied document title is explicit; source reference is fixed generic offline-email provenance. No automatic review. Subject/from/Message-ID are not dedup identities or copied into document metadata/audit; original headers remain only in creator-readable raw email. Exact raw-message SHA256 dedup is per owner+scope and persists as a tombstone after forget. Same exact message returns current linked document without changing title/review/revisions; changed forwarding bytes preserve a distinct original/document and rely on visible duplicate hints for review. No cross-owner/scope count disclosure or business-duplicate/import suppression claim.
- At most4MiB active raw email bytes per creator, in addition to existing document quotas. Existing document record/active/version/byte limits remain. Intake creates document, original/version, envelope and metadata audit in one transaction; failure exposes no partially imported document or receipt. Current authority is rechecked after parser/row waits. Concurrent exact submissions serialize to one record. PDF extraction reuses the existing isolated worker/status contract; manual `.eml` input alone is not a live adapter/job execution claim.
- Envelope immutable while active: exact raw bytes/hash/size, initial filename/checksum, document identity/owner/scope/time. Provenance receipt pins current document revision and explicitly states whether initial attachment matches current bytes after replacement. Raw email export is creator-only and acknowledged unmanaged copy. Parent source replacement never rewrites the original envelope. Logical restore verifies exact bytes/source link/tombstones; no consumer is activated by restore.
- Forgetting the document atomically scrubs raw envelope/filename/attachment checksum with document originals/history and invoice/plans. Keep only bounded identity/raw-message checksum/size/time tombstone metadata for exact replay denial. No independent raw-email history or header store. Old backups/downloads cannot be recalled; full older-backup suppression remains a separate retained gate. Denial or audit failure rolls back all changes; terminal forgetting remains available at quota.
- UI import/provenance state stays in memory, clears on scope/source/revision/view/session change, never retries automatically and never renders email HTML/headers. Explicit load/open/download and readable replay/unsupported/conflict outcomes; late replies cannot cross a view. Email export after source replacement is visibly the original intake, not the replacement. Synthetic data only.

## Acceptance

1. Valid plain/PDF original and raw-email byte fidelity, strict MIME/base64/type/path/line/part/header limits, unknown/unsupported/ambiguous rejection and inert instructions.
2. Exact replay before/after source review/replacement, concurrent retry, per-owner/scope separation, quota, tombstone denial, current source provenance/export, atomic aggregate forgetting and audit-failure rollback.
3. Current grants/creator/private/admin/session/CSRF/origin negatives, actual expiry/lock/concurrency and restricted SQL table/column/immutable/tombstone guards.
4. Migration 0029 round trip/full logical recovery checks raw bytes/provenance/tombstones; no real provider activation or older-backup certificate.
5. Trusted HTTPS/mobile import→document review→invoice plan, repeated email, raw original download, unsupported rejection and late-view clearing. CI-default Compose owner `butler`/runtime refusal; native PG/restore intentionallypostgres.
6. Required checks/security/privacy, canonical docs/149-ID reconciliation, one coherent commit/PR/push; expected CI then stop, no polling/merge.
