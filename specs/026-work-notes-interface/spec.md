# 026 — Synthetic Work capture and review screen

Outcome: a current workspace user can browse synthetic notes, choose existing source/party/policy labels, request a draft save, inspect/review an exact version, request confirmation, correct it or request forgetting in one screen. The existing one-shot local executors remain separate; pending is never displayed as applied. No UUID entry, real employer data, inference, connector, new worker or execution authority.

Independent default-disabled interface and existing per-action flags. An explicit optional complete-interface overlay enables only the existing synthetic lifecycle flags. Existing change provisioning supplies all required scoped privileges; no new database object/grant/public table or dependency. New read-only catalogue/inspection APIs require HTTPS/Host/Origin/session/CSRF/current synthetic workspace grant before private credentials, same-target/restricted-role checks and current expiry checks. No generic owner credentials or note write API.

Catalogue setup returns at most 25 each of notes/sources/parties/policies/current-session requests, with per-section UUID pagination. Options use active scoped sources/parties and explicit policies; notes use metadata-only visibility plus current RLS-eligible labels, never expired/revoked content. Request metadata is original-actor/session only; capture/change private rows and public confirmation metadata are bounded/merged. Optional nonce+operation lookup recovers ambiguous responses without creating committed write evidence or authorizing orphan preparation. Pending counts are metadata snapshots, not application guarantees. Unknown owner/date stay unknown; policy/source selection is explicit.

Inspection returns one currently live draft/confirmed note, exact revision/hash and selected reference labels, with private prepared-read and metadata-only identity audit before response release. Maximum 60-second preview/catalogue validity is bounded by session/content/party expiry. Future writes reauthorize through existing APIs. UI validates server schema/workspace/bindings, never treats content as executable instructions and stores no private data in local/session storage, URLs, logs or exports.

UI keeps frozen request nonces/payloads for deliberate same-request retry after ambiguity, recovers status by nonce/operation/target/revision, and never silently creates another mutation or retries automatically. Confirmation explicitly reviews the displayed revision/hash before requesting application. A pending/uncertain action blocks another submission in that screen until reconciled or server lifetime ends. Forget requires a clear modal. Session/view/workspace changes, denial, secret failure, expiry and late responses clear private payloads and abort requests; only minimal request references may survive payload expiry for authorized reconciliation. No stale review/confirmation handle survives a new preview or correction.

Acceptance: strict/default/scope/CSRF/role/secret denial before payload; bounded pagination and cross-workspace/session isolation; metadata-only hidden-note cleanup; audit/expiry failures return no content; request recovery never supplies identity intent evidence; strict frontend parsing, frozen nonce and malformed-response failure; actual verified-TLS browser capture → local save → review/confirm → correction/forget, pending truthfulness, request recovery, denial/late-response cleanup and mobile layout. Source checks, PostgreSQL, restore and exact-head CI before readiness. Independent key/derived/older-backup/full-host and real-content acceptance remain open.
