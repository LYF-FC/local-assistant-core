# Engineering rules

Read `.specify/memory/constitution.md` and the relevant feature contract before meaningful changes. Preserve FastAPI/PostgreSQL/React, explicit scopes, Windmill/Home Assistant boundaries and separately reviewed accelerated/native components.

Use synthetic data only. Never commit private records, credentials, `.env`, runtime exports or host-specific plans. No production access/outbound AI side effect. Use locked uv/npm dependencies and `make check`; permission/migration/audit changes need negative tests and actual disposable PostgreSQL evidence. Keep commit-before-release audit, full restoration tests, real role/idempotence checks and current identity authority.

Use specify/clarify/plan/checklist/tasks/analyze/implement/converge for meaningful work. [PROJECT_MASTER.md](PROJECT_MASTER.md) is the single authority for scope, MVP gates, delivery status and priorities; ROADMAP, CONTEXT, CHANGELOG, BACKLOG_STATUS and similar files are sequencing views or dated history and must not carry independent current status. The register owns requirement text and evidence pointers; `docs/MVP_ACCEPTANCE.md` owns acceptance procedures; specs and feature contracts own behavior and limits. Rule: update the authoritative source, then regenerate derived views (`python3 scripts/build_feature_overview.py`); never hand-edit `FEATURE_OVERVIEW.md` or `FEATURE_DASHBOARD.html`. Keep implementation, integration (merged), testing, verification and acceptance as separate facts, each with evidence; unknown stays unknown, a synthetic capability is never described as a real integration, in-process tests are not restart proof, and only the owner accepts a gate (naming environment and scope). Mark merged delivery only after merge with a verified PR number and merge commit; branch engineering and host acceptance are different states. A PR that changes delivered behavior updates its gate entry in the master and any affected register row in the same PR.

Prepare coherent batches and local checks before pushing. Use the conservative CI scope policy and mandatory scope/final gate; unknown/critical changes and scheduled/manual events require full coverage. Deliberate skips are not test-pass evidence. Full exact-main evidence and separately reviewed host/recovery gates are required for production/package certification. Keep readonly tokens, SHA-pinned actions, no pull_request_target and no production secrets or database/test-result caches. Record final CI evidence in PR metadata without evidence-only source pushes. Never merge automatically.
