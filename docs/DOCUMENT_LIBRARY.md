# Local document library — spec 048

Open Documents after signing in. Select Shared household, Member A private or Member B private from your current grants. Upload a nonempty `.txt` or `.md` basename: strict UTF-8, at most 128 KiB original/32,000 Unicode characters, no NUL. HTTPS permits a 192 KB request only for POST upload/replacement paths to accommodate base64 overhead; other requests retain the 64 KB proxy bound. Titles are 160 characters; source references are 512 printable characters. Original BOM and CRLF bytes are preserved and hashed. Markdown/HTML/prompt text remains inert text; no file is executed or rendered as markup.

Uploads begin unreviewed. Open the document, choose Correct and review, inspect the text and explicitly attest review. This is a human attestation, not independent verification. Reviewed documents can produce deterministic cited excerpts, up to 50 original logical lines and 16 KiB UTF-8. Lines split on LF (retaining any CR), with a final empty line counted. Citations contain stable ID, revision, checksum, filename, source reference and exact line bounds. There is no generated answer or model integration. Search is literal in current title/text, including `%` and `_`; it uses JSON POST bodies, never URL parameters. The API defaults to reviewed-only; the library explicitly starts with all documents and offers a reviewed-only filter. Unreviewed search results cannot produce cited retrieval.

Household members read current shared documents and originals. Only the creator can correct/review/replace, inspect history or previous originals, and forget. Private documents stay creator-only even for another person holding the same private scope. Technical administration provides no content grant. Current membership, active account, live session, CSRF and HTTPS Origin are checked on each operation. Current revisions are pinned for excerpts/downloads/writes; after conflicts, discard and reload to review current state. No changes retry automatically.

Replacement preserves the stable ID and full previous version but resets review. Metadata/review corrections also preserve a version with exact original bytes. History is paged by 25 versions. Explicitly acknowledge unmanaged-copy limits before any original download or page export. Original downloads are client-verified against SHA-256, use generated ID/version filenames and `application/octet-stream` attachments. Current page JSON contains metadata, owner/actor/scope, schema, timestamps, filters and continuation; it is not a whole-library backup or original/history export. History and originals have separate bounded operations. Scope/view/session changes discard unsaved interface drafts; no library drafts go in browser storage.

Limits per creator: 64 active documents, 128 lifetime records including tombstones, 50 retained content versions/document, 8 MiB logical original plus identical UTF-8 text bytes across all versions. Metadata corrections also consume version quota. These are logical limits, not a physical PostgreSQL disk guarantee. Forget remains available when limits are reached. It terminally removes all managed current/history metadata, text, hashes and original bytes; only IDs, ownership/scope, revisions, operations and timestamps survive. It does not erase database WAL, older dumps or downloaded/unmanaged copies; secure erasure and latest suppression reconciliation remain separate archive/recovery work.

## Storage and operation boundary

This is a bounded development/test staging library. Originals are temporarily PostgreSQL BYTEA, committed atomically with version history and minimal audit. Synology remains the intended durable archive, and PostgreSQL remains on its local live database filesystem. No NAS, PDF/OCR, mailbox, remote fetch, invoice processor, local model or production content activation is added. Do not treat this feature as production archive/key/derived-copy/old-backup acceptance. Production/staging startup remains refused.

Migration `0022_document_library` creates current/version tables and seals identity, original provenance, terminal tombstones and history. Runtime receives select/insert/update on current records and select/insert plus NULL-only post-forget scrub on version bytes/snapshot, with no delete/truncate/DDL, audit read or scope administration. Reapply privileged development role setup after migration. Downgrading to 0021 intentionally destroys document originals/history; export and use a disposable test database before migration reversal. Ordinary migration-owner SQL is sealed; a superuser that alters triggers remains trusted infrastructure.

Use `make check`, the complete disposable PostgreSQL integration suite, `scripts/test-db-restore.sh` and `scripts/test-containers.sh`. The logical restore drill retains exact originals, correction history and scrubbed tombstones and rechecks seals. Before an actual restore, stop consumers and follow existing restored-session quarantine/recovery procedures. A logical dump can restore older document content; this batch supplies no newer document forgetting ledger or production recovery certificate. Four full exact-head hosted checks remain mandatory before PR readiness.
