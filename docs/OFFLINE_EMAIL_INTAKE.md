# Bounded offline email intake

[Spec 058](../specs/058-offline-email-intake/spec.md) imports a synthetic `.eml` and its single attachment into the existing document/invoice workflow. This is an offline provenance/intake foundation for DOC-01 and MVP-03. No mailbox is connected, no message is sent, no model runs and no file is filed. No data leaves the installation.

## Import and review

In Documents choose **Import forwarded email…**, select the intended scope, enter a document title and upload the synthetic original `.eml`. A new attachment starts unreviewed; inspect its original and extraction before explicitly reviewing invoice fields or preparing a filing plan. Email text/headers are untrusted source material, not instructions or authenticated sender identity. Subject/from/Message-ID are preserved only in the raw original and never become automatic document metadata or dedup authority.

The supported format is deliberately small: canonical base64 upload of at most 256 KiB raw mail, at most 4,096 physical lines and 1,024 bytes/line, four Content-Type header lines and eight delimiter-like lines before parsing. Require MIME-Version 1.0 and a supported multipart/mixed boundary, at most two direct leaves: optional plain-text body plus exactly one base64 attachment. No nesting, message/rfc822, HTML/alternative parts, ambiguous/duplicate MIME/security headers or silent attachment omission. The attachment must have a safe text/Markdown/PDF basename and matching text/plain or application/pdf type. Existing 128 KiB original/32,000-character/PDF worker and OCR limits remain. Unsupported/ambiguous mail fails atomically rather than producing a partial source. Parsing uses only the bounded standard-library MIME subset; it fetches nothing.

An exact original-message checksum is deduplicated only within the current creator and scope. Reimporting identical bytes reuses the current document, preserving its title, review and replacements; the new title is ignored on replay. Changed forwarding bytes preserve a separate original/source even when attachment bytes match. Use existing visible duplicate hints for human review; this is not semantic forwarding dedup, import suppression or proof of business identity. Concurrent exact requests serialize; retry after an uncertain acknowledgement is explicit, never automatic.

## Original email privacy and provenance

The attachment can be shared, but raw email and its provenance remain creator-only. Administration/same-private-scope grants do not override content ownership. Open **Original email provenance** to inspect initial source revision 1, original email checksum/size and initial attachment name/checksum. Replacement does not rewrite the envelope: the receipt says whether initial attachment bytes match the current document. Every response pins the current document revision and current permissions.

Original-email download requires acknowledgement that unmanaged copies/old backups cannot be recalled. The API export is versioned JSON with canonical raw base64; the UI verifies byte count and SHA256 before downloading the exact original `.eml`. Headers/body are never rendered as HTML or followed as links. UI file/provenance drafts live only in memory and clear on scope/source/revision/view/session changes; late replies cannot repopulate a different view.

## Retention, quotas and recovery

At most4 MiB active raw mail per creator is retained in addition to existing document record/version/original quotas. Document, first original/version, envelope and metadata audit commit in one transaction. Quota, parser, authority or audit failure exposes no partial intake receipt/document. PDF extraction retains existing explicit unavailable/failure states and never implies review.

Document forgetting atomically scrubs raw mail, its filename and attachment checksum along with document originals/history and invoice/plan copies. A bounded private tombstone retains document/creator/scope identity, **exact-message checksum**, byte count and timestamps solely to deny exact replay. It contains no mail/attachment content or names; the UI discloses this before import and forgetting. Same-message reimport after forget returns gone. Audit/logs contain IDs/revisions/operation only, never headers, values, original payloads or content hashes. Old backups/downloads remain outside recall; independent older-backup suppression remains an open acceptance gate.

Migration `0029_email_intake` follows 0028 and adds one protected original-envelope table. The runtime can select/insert and update only scrub columns; SQL guards seal active bytes/identity/checksum and permit terminal scrub only after parent forgetting. No table/history duplicate of raw mail is created. Logical backup/restore includes byte-identical raw mail, initial attachment lineage and forgotten replay tombstones; restore activates no consumer. Downgrade removes raw-mail provenance and needs a protected backup/export with reviewed rollback. Stop writers for migration/rollback; older application versions do not implement envelope forgetting and are not certified to write/forget email-linked sources under this contract.

Restricted live mailbox/MailPlus feasibility, configured sender/source rules, broader MIME/attachment formats, email job cursors/recovery, semantic forwarded-copy reconciliation, destination authorization and exactly-once filing remain retained work. [Filing-plan approval](INVOICE_FILING_PLANS.md) stays non-executable. DOC-04 file inventory/audit/rollback and all installation/later requirements remain distinct; this increment does not certify full DOC-01/MVP-03, private adoption or a real provider.
