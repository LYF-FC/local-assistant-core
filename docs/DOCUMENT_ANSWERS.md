# Scoped document answers — spec 053

Choose **Document answers**, a supported assigned scope, a question language and an evidence budget. Ask about reviewed current sources. Base setup returns **source excerpts · local model disabled** and makes no model request. Explicitly configured local selection can return exact quotations, abstain for insufficient/conflicting evidence or expose unavailable/invalid selection. It cannot supply quotation text, links, tools or executable actions. The application constructs every quotation from its current source lines.

This is source-backed extractive answering, not free-form synthesis, multi-turn conversation, semantic/vector retrieval or independent verification of source truth. English/French/Spanish question preferences do not translate quotations. OCR remains uncertain and needs comparison against the original. Those broader capabilities and real-model quality/activation remain retained acceptance gates; all 149 scope IDs remain.

## Evidence and permissions

Only current active reviewed documents from one selected scope are eligible. Private records remain creator-only, even for a member with the same scope; technical administration adds no content access. Unreviewed, failed extraction, forgotten and historical records are excluded. Search uses up to eight distinct lexical terms after a small fixed multilingual stop-word filter, ranks matches and selects at most three documents with eight-line evidence windows. This is a bounded selection, not exhaustive research; it may miss relevant sources. Oversized evidence fails rather than silently truncating the selected window.

Source metadata includes stable document ID/revision, original SHA-256 and source reference; PDF/OCR evidence also preserves derived hash, engine/build and intersecting page spans. Selected answers contain at most five non-overlapping exact line ranges and 8 KiB of quotation/provenance data. Model references cannot create sources, invent text or cross the supplied evidence window. **Open current source** rechecks current access in Documents and may show a newer revision. Source references/markup remain inert text; no external link is fetched.

## Dispatch, audit and retention

Preparation commits metadata-only audit before context leaves the API process. A fresh transaction reauthorizes the user/session/CSRF/scope and unchanged configuration, locks and rebuilds the exact source revisions, then performs bounded selection and audited release. Source/authority drift prevents dispatch. Locks serialize concurrent edits/revocations; expiry is rechecked before response. A failed preparation audit prevents model dispatch, and a failed release audit withholds the answer.

Audit records only request identity, source IDs/revisions and evidence/quotation line ranges, byte counts, outcome, dispatch flag and configured model provenance. No question, prompt, quotation, generated content, provider error or question hash is persisted. `model_invoked` records attempted or possible dispatch, not successful inference. An interrupted preparation/dispatch can have unknown completion; it never triggers an automatic retry. No conversation/context cache or browser storage is introduced. Responses expire within 60 seconds/session expiry. Scope, question, language, budget, view or session changes clear/cancel the displayed snapshot. Observed responses cannot be retroactively erased; source changes elsewhere can make a snapshot stale before expiry.

Questions are capped at 500 characters, 1–8 KiB serialized evidence and 30 requests per user per 15 minutes. The selector permits one active transport per API process and rejects busy work without queuing. A trusted protocol subprocess receives bounded stdin, inherits no credentials/proxies or database descriptors, returns bounded JSON and is killed at a 12-second wall deadline—including slow headers. HTTP response bodies are capped at 32 KiB. Source locks are held only through bounded dispatch/release, not an unbounded model wait.

## Disabled-by-default local adapter

`BUTLER_DOCUMENT_ANSWERS_ENABLED` defaults false. Future separately authorized use requires an explicit `BUTLER_DOCUMENT_ANSWER_MODEL` with tag, exact 64-hex `BUTLER_DOCUMENT_ANSWER_DIGEST` and the existing approved local-only `BUTLER_OLLAMA_URL`. No question can supply or change these settings. The adapter checks the selected local manifest before/after, requires a nonempty local GGUF descriptor and refuses remote-model metadata, redirects, environment proxies, tool calls, incomplete output, duplicate fields and invalid citations. It never downloads, pulls, switches models or falls back to a remote provider. Each request uses a fresh two-message reference envelope, no conversation history, no tools, a 256-token selection budget, a requested 16,384-token context ceiling and zero keep-alive.

No weights, license, model architecture or hardware profile is selected here. Before real activation, verify the exact runtime/model/template, license, capacity and context behavior, offline egress restrictions, retention/logging, FR/ES/EN relevance/abstention and cancellation/resource behavior. A timeout stops this transport and withholds output; it cannot promise that an already-authorized runtime has stopped its own computation or erased context. A configured runtime is a trusted local component, not a cryptographic attestation boundary. RND-04/05 remain open; a declared manifest alone does not certify model quality, privacy or capacity.

The [chat schema](https://docs.ollama.com/api/chat) and [local manifest interface](https://docs.ollama.com/api/tags) are isolated behind a replaceable adapter. `infra/core/answers-synthetic.override.yml` starts only a simulated service on the disposable API's loopback namespace, with no model weights, database credentials or access to an existing host model. Base configuration never starts it. Do not apply this fixture overlay to a private deployment.

## Recovery and verification

No schema change, content duplication or answer-history migration is introduced. Existing document/original/history/archive export, managed forgetting and DB-plus-separate-archive restoration remain authoritative. New queries recheck restored current grants, review and source state; restored sessions remain subject to the existing quarantine. Old-backup/key/independent-host acceptance is unchanged.

Synthetic tests cover source-only/no-source behavior, multilingual lexical selection, ranking/budgets/rate limits, malformed model replies, exact citations, audit failures, source/configuration/expiry drift, restricted PostgreSQL and actual locks/committed audit. A real local HTTP trickle test verifies the hard deadline. Trusted-HTTPS browser tests cover a simulated model, source navigation, private/shared separation, abstention/failure, stale-response clearing, forgetting and mobile layout. Final exact-head verification belongs in PR metadata. No real integration, production activation, private data migration or auto-merge.
